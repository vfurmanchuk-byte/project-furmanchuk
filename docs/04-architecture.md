# 04. Архітектура системи «TechFix»

## 1. Стиль архітектури

Обрано **багаторівневу (layered) архітектуру з елементами MVC** — типовий для вебзастосунків
середнього розміру підхід, який дає чіткий поділ відповідальності й дозволяє одному розробнику
вести проєкт без надмірної інфраструктури (мікросервіси тут були б передчасним ускладненням).

| Рівень | Відповідальність | Компоненти |
|---|---|---|
| Подання (Presentation) | відображення, форми, валідація на клієнті | шаблони views, віджети, Bootstrap 5 |
| Контролери (Application) | маршрутизація, права доступу, сценарії запитів | RequestController, EstimateController, AdminController |
| Домен (Domain / Service) | бізнес-правила, переходи станів, розрахунок кошторису | RequestService, EstimateService, WarrantyService |
| Доступ до даних (Persistence) | читання й запис, транзакції | ActiveRecord-моделі, міграції |
| Зберігання | дані й файли | MySQL 8, файлове сховище для PDF і фото |

## 2. Технологічний стек

- **Мова та фреймворк:** PHP 8.2, Yii2 (basic/advanced template), Composer.
- **База даних:** MySQL 8 (InnoDB, utf8mb4), міграції Yii для відтворюваної схеми.
- **Фронтенд:** серверний рендеринг, Bootstrap 5, мінімум JavaScript (валідація форм, фільтри).
- **Вебсервер:** Nginx + PHP-FPM; у розробці — вбудований сервер `php yii serve`.
- **Автентифікація:** сесії Yii, RBAC (`yii\rbac`) з ролями client / master / manager / admin.
- **Документи:** генерація PDF (mPDF або Dompdf) для акта приймання й гарантійного талона.
- **Журналювання:** таблиця `audit_log` + логи застосунку.

## 3. Структура коду

```
project-furmanchuk/
├─ config/            конфігурація застосунку, маршрути, параметри
├─ controllers/       обробники запитів (тонкі, без бізнес-логіки)
├─ models/            ActiveRecord-моделі та форми
├─ services/          бізнес-логіка (переходи станів, кошторис, гарантія)
├─ views/             шаблони (layout, черга, картка заявки, звіти)
├─ migrations/        міграції схеми БД
├─ web/               точка входу index.php, статика
└─ docs/              ця документація
```

Правило залежностей: контролер → сервіс → модель. Контролер не звертається до БД напряму,
модель не знає про HTTP, сервіс не знає про шаблони. Це дозволяє тестувати бізнес-правила
(наприклад, заборону переходу «Діагностика» → «Видано») без підняття вебсервера.

## 4. Модель даних (основні таблиці)

| Таблиця | Призначення | Ключові поля |
|---|---|---|
| `client` | клієнти | id, full_name, phone, email |
| `device` | пристрої клієнтів | id, client_id, type, brand, serial_number |
| `request` | заявки на ремонт | id, number, device_id, master_id, status, access_token, created_at |
| `estimate` | версії кошторису | id, request_id, version, total, state |
| `estimate_item` | позиції кошторису | id, estimate_id, kind, title, price, quantity |
| `work` / `spare_part` | довідники робіт і запчастин | id, title, price, stock |
| `warranty` | гарантійні талони | id, request_id, starts_at, ends_at |
| `audit_log` | журнал дій | id, user_id, entity, entity_id, action, created_at |

Індекси: `request.status`, `request.master_id`, `device.serial_number`, унікальний `request.number`.

## 5. Розгортання

1. `composer install` → налаштування `config/db.php` (доступи до MySQL).
2. `php yii migrate` → створення схеми й початкових довідників.
3. `php yii rbac/init` → ролі та права.
4. Вебсервер спрямований на каталог `web/`; права запису — на `runtime/` і `web/uploads/`.
5. Резервне копіювання: щодобовий `mysqldump`, зберігання 30 днів (NFR-04).

## 6. Безпека

- Паролі — `password_hash()` (bcrypt), ніколи у відкритому вигляді.
- Доступ за токеном до сторінки статусу: токен генерується випадково (32 символи), перевіряється
  разом із номером заявки, не індексується пошуковими системами (`noindex`).
- Захист від CSRF — вбудований у Yii для всіх форм, що змінюють стан.
- Захист від SQL-ін'єкцій — параметризовані запити через AR/Query Builder.
- Розмежування прав перевіряється на сервері (RBAC), а не приховуванням кнопок в інтерфейсі.
- Журнал дій (`audit_log`) — джерело істини для розбору спірних випадків із клієнтом.

## 7. Зв'язок із нефункціональними вимогами

| NFR | Як забезпечується |
|---|---|
| NFR-01 (до 1 с) | індекси на статусах і майстрі, пагінація черги, відсутність N+1 запитів (eager loading) |
| NFR-02 (до 20 користувачів) | одного PHP-FPM пулу й MySQL достатньо; горизонтальне масштабування не потрібне |
| NFR-05 (безпека) | RBAC, CSRF, хешування паролів, валідація на сервері |
| NFR-06 (українська) | локалізація Yii (`uk-UA`), формати дат і сум через `Yii::$app->formatter` |
